# lastread

Перевод [README.md](README.md). Если тексты расходятся, верен английский.

`lastread` снимает образ умирающего диска или раздела через [GNU ddrescue](https://www.gnu.org/software/ddrescue/)
стараясь уменьшить нагрузку на него, а затем достаёт из образа файлы. С больного диска только читается; на него ничего
не пишется.

Это один bash-скрипт вокруг `ddrescue`. Что он добавляет:

- **Продолжение с любого места.** Фаза определяется по карте ddrescue, поэтому после любой остановки — перегрев,
  Ctrl+C, диск отвалился от шины, перезагрузка — достаточно запустить ту же команду, и работа продолжится.
- **Сторож.** Раз в `--interval` секунд проверяются температура диска (`smartctl`) и то, что диск вообще отвечает.
  Слишком горячо — ddrescue останавливается и продолжает, когда диск остынет.
- **Отложенные зоны.** Места, где диск зависает, откладываются; сначала читается всё остальное, а зоны — в самом
  конце, по одной, попеременно с начала и с конца, пока не останется нечитаемое ядро.
- **Отвалившийся диск.** ddrescue останавливается до того, как пометит весь остаток плохим (пропавший диск отвечает
  ошибкой на каждое чтение, мгновенно). Следы возвращаются в «не прочитано», а на SATA/SAS диск возвращается
  пересканированием его SCSI-хоста — без выключения питания.
- **Структуры тома — первыми.** На NTFS таблица разделов, загрузочный сектор, `$MFT` и индексы каталогов, а затем пути,
  названные через `--first`, читаются раньше остального диска: у умирающего диска порядок чтения решает, что уцелеет.
- **Файловый уровень для NTFS, ext2/3/4 и FAT/exFAT** без монтирования образа (The Sleuth Kit), в том числе для образа
  диска целиком с таблицей разделов: какие файлы целы, какие повреждены, спасение только выбранных файлов, раскладка целых файлов с их
  временем и обнаружение мусора, который диск отдал *без ошибки*.
- **Для долгих спасений.** `--triage` (короткая проверка диска только чтением, с вердиктом), `--status` (прогресс, не
  трогая диск, в том числе JSON), `--on-event` (программа запускается, когда диск греется, отваливается, требует
  выключения питания …) и `--print-service` (юнит systemd, который сам продолжит спасение после выключения питания).

Инструмент ничего не чинит и намеренно не пишет на исходное устройство. Во время спасения он пытается установить
флаг ядра «только чтение» как дополнительную защиту; если это не удалось, предупреждает и продолжает без неё.
Никакая программа не гарантирует, что дальнейшее чтение не ухудшит состояние неисправного диска.

## Когда не стоит им пользоваться

Не используйте его, если данные ценные, а поломка похожа на механическую. **Несите диск в лабораторию
восстановления данных**, если видите хоть одно из:

- щелчки, стук, скрежет или писк из диска;
- диск не определяется вовсе или определяется с неверным размером или именем;
- диск роняли, заливали, он горел или пахнет гарью;
- SSD показывает 0 байт или странное имя модели (отказ контроллера);
- данные незаменимы, и терять даже часть нельзя.

Каждая лишняя минута работы умирающего диска может стоить данных, а лаборатория умеет то, что программе недоступно.
`lastread` — для распространённого среднего случая: изношенный, но живой диск — плохие сектора, медленные места,
перегрев, нестабильная связь — когда данные важны, а диск ещё отвечает.

И ещё: никогда не запускайте на исходном диске `fsck`, `chkdsk`, `ntfsfix` и не монтируйте его на запись.
Вся работа — с образом.

## Требования

| Что | Версия (проверено) | Для чего |
| --- | --- | --- |
| Linux, bash | bash ≥ 4.4 (5.2) | всё |
| GNU ddrescue | ≥ 1.27 (1.27) | снятие образа |
| util-linux (`lsblk`, `blockdev`, `flock`, `runuser`) | 2.39 | всё |
| GNU coreutils (`numfmt`, `stat`, `truncate`, `dd`, …), `grep` с `-P`, awk (mawk или gawk) | 9.4, 3.11, mawk 1.3.4 / gawk 5.2 | всё |
| smartmontools ≥ 7 (для `smartctl -j`) и jq | 7.4, 1.7 | сторож температуры (по желанию) |
| The Sleuth Kit | 4.12 (4.12.1) | файловый уровень (по желанию) |
| whiptail | любая | окно `--pick` (по желанию; без него — обычные вопросы) |
| systemd (`systemd-inhibit`) | любая | чтобы машина не засыпала (по желанию) |

Проверено на Ubuntu 24.04 (ядро 6.8). Чтобы читать устройство, нужен root; `--inventory` и раскладка из готового
образа работают и без него.

## Установка

Это один файл:

```bash
sudo install -m 755 lastread /usr/local/bin/lastread
```

Чтобы заменить копию, в которой **сейчас идёт спасение**, запишите новую версию во временный файл рядом и
переименуйте его поверх (`mv`): bash читает скрипт по ходу выполнения, и перезапись файла на месте может сломать
работающий экземпляр.

## Быстрый старт

1. Найдите устойчивое имя диска или раздела. `/dev/sdX` может смениться, когда отвалившийся диск вернётся:

   ```bash
   ls -l /dev/disk/by-id/
   ```

   Источник не должен быть смонтирован. Для файлового уровня снимайте **раздел** (`...-part1`), а не диск целиком.

2. *(По желанию, рекомендуется.)* Короткий взгляд на диск до долгого запуска. Он только читает:

   ```bash
   sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK-part1 --triage
   ```

   Осмотр действительно читает диск и создаёт нагрузку; пропустите его, если дополнительные чтения нежелательны.

   Печатает сведения о диске, SMART (если диск его показывает), сообщения ядра о диске и девять пробных чтений по
   мегабайту, затем вердикт — зелёный, жёлтый или красный — и предлагаемые параметры. Красный значит, что диск почти не
   отвечает: см. «Когда не стоит им пользоваться».

3. Снимите образ. Каталог должен существовать, вмещать всё устройство целиком и находиться **на другом физическом
   диске**:

   ```bash
   sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK-part1 --dir /mnt/big/rescue
   ```

   В каталоге появятся `ИМЯ.img`, `ИМЯ.map` и `ИМЯ.logs/` (`ИМЯ` — последняя часть пути к источнику, если не задан
   `--name`; для имени, которое может измениться, например `/dev/sdb1`, `--name` обязателен: следующий запуск должен
   найти тот же образ). Остановить можно в любой момент; чтобы продолжить, запустите ту же команду.

4. Посмотрите, что повреждено, и заберите целое — диск больше не нужен:

   ```bash
   sudo lastread --inventory --dir /mnt/big/rescue --name ata-EXAMPLE_DISK-part1 \
       --extract --extract-to /mnt/recovered
   ```

   Списки лежат в `ИМЯ.logs/`: `inventory-intact.txt`, `inventory-incomplete.txt`, а после полного прогона —
   `damaged-files.txt` и `suspicious-files.txt`.

Сначала можно запустить с `--dry-run`, чтобы увидеть, что инструмент собирается делать.

## Как идёт работа

Фаза каждый раз определяется по карте, так что больше ничего помнить не нужно:

| Фаза | Что происходит |
| --- | --- |
| `meta` | только NTFS и один раз: таблица разделов, загрузочные секторы, `$MFT`, индексы каталогов, затем данные путей `--first` — читаются раньше всего остального. Пропускается для других файловых систем, с `--no-meta-first` и `--no-fs`. |
| `copy` | ddrescue читает всё, что читается быстро; плохие и медленные места пропускаются (`ddrescue -n`). Всегда начинается с прохода 1 от текущей позиции. |
| `scrape` | пропущенные области читаются посекторно |
| `retry` | нечитаемые секторы пробуются ещё `--retries` раз |
| `zones` | отложенные зоны — в последнюю очередь, по одной, попеременно с начала и с конца |
| `report` | сводка; при файловом уровне — список повреждённых файлов |
| `extract` | с `--extract`: целые файлы копируются из образа |

Код выхода: `0` готово, `1` ошибка, `2` остались только застрявшие отложенные зоны (см. `--give-up-zones`), `3` диск не
отвечает и нужно выключить питание, `130` прервано. (`--triage` возвращает `4` при красном вердикте.)

Файлы в `ИМЯ.logs/`: `rescue.log` (журнал запуска), `events.log` и `rates-*.log` (журналы событий и скоростей
ddrescue), `ddrescue-ФАЗА.log` (его вывод), `zones` (отложенные зоны), `scsi-host` (что пересканировать), `state` (его читает
`--status`), `meta.done`/`first.done` (фаза «структуры первыми») и списки.
Устройство частей описано в [docs/how-it-works.md](docs/how-it-works.md) (на английском).

## Параметры

```
lastread ИСТОЧНИК [параметры]
lastread --inventory | --status [--json] [--name ИМЯ] [параметры]
lastread ИСТОЧНИК --triage
lastread ИСТОЧНИК [параметры] --print-service
```

Полный список со значениями по умолчанию — `lastread --help`. Группы:

**Размещение** — `--dir КАТАЛОГ` (по умолчанию текущий; должен существовать), `--name ИМЯ` (обязателен, если источник
не под `/dev/disk/` или `/dev/mapper/`).

**Сторож** — `--stop °C` (48), `--resume °C` (44), `--interval СЕК` (60), `--temp-cmd ПРОГРАММА`,
`--smart-type ТИП`, `--no-temp`. `ПРОГРАММА` запускается с устройством диска целиком единственным аргументом и печатает
°C (оболочка не участвует); значение по умолчанию можно задать через `$LASTREAD_TEMP_CMD`. Без рабочего источника
температуры инструмент так и говорит и работает без сторожа. Гистерезис обязателен: `--resume` ниже `--stop`.

**Чтение** — `--min-rate СКОРОСТЬ`, `--skip-size РАЗМЕР`, `--retries N` (3), `--reverse`, `--start-at ПОЗИЦИЯ`.
Они задают `ddrescue -a`, `-K`, `-r`, `-R` для фазы copy (`--start-at` — только для первого запуска copy).

**Отложенные зоны** — `--add-zone ОТ-ДО` (разово), `--give-up-zones`, `--zone-margin РАЗМЕР` (1G),
`--zone-min-progress РАЗМЕР` (16Mi).

**Отвалившийся диск** — `--rescan-pause СЕК` (60), `--rescan-attempts N` (3), `--no-rescan`, `--kernel-timeout СЕК`
(180; 0 — не трогать ядро), `--artifact-limit РАЗМЕР` (1G), `--artifact-bad РАЗМЕР` (16Mi).

**Файловый уровень** — `--extract`, `--extract-to КАТАЛОГ`, `--include ПРЕФИКС` (повторяемый), `--map ИСТОЧНИК:КУДА`
(повторяемый), `--owner ПОЛЬЗОВАТЕЛЬ[:ГРУППА]`, `--file-mode РЕЖИМ` (0664), `--dir-mode РЕЖИМ` (0775),
`--extract-damaged`, `--inventory`, `--pick`, `--file ЧАСТЬ_ПУТИ` (повторяемый), `--no-fs`.

**Порядок** — `--first ПУТЬ` (повторяемый): читать этот каталог или файл тома сразу после его структур;
`--no-meta-first`: без фазы «структуры первыми».

**Образы дисков целиком** — `--partition N`: в каком разделе таблицы образа лежит том, если файловую систему, которую умеет читать файловый уровень,
несут несколько разделов.

**Безопасность и уведомления** — `--no-readonly` (не ставить флаг «только чтение» ядра на источник), `--on-event
ПРОГРАММА` (по умолчанию из `$LASTREAD_ON_EVENT`), `--print-service`.

**Осмотр** — `--triage` и `--triage-timeout СЕК` (20); `--status` и `--json`.

**Тихая порча** — `--suspect-pattern RE` (повторяемый), `--suspect-zeros РАЗМЕР` (128Ki), `--no-suspect-check`,
`--recheck-garbage`.

**Проверка** — `--verify` (с `--extract`).

**Общие** — `--dry-run`, `--help`, `--version`.

Размеры принимают `k`/`M`/`G`/`T` (степени 1000) и `Ki`/`Mi`/`Gi`/`Ti` (степени 1024).

## Безопасное продолжение

Храните образ и карту вместе: если образ отсутствует или короче прочитанных по карте областей, продолжение запрещено.
Проверка не обнаруживает подмену образа файлом того же размера или разреженные дыры. При первом запуске lastread
сохраняет доступные идентификаторы устройства и геометрию раздела в `ИМЯ.logs/source.identity` и сверяет их при
продолжении и переподключении. Если идентификатор изменился или недоступен, программа останавливается; самостоятельно
проверив источник, можно принять новую идентичность параметром `--accept-source-change`. После этого уберите параметр,
в том числе из systemd-юнита, чтобы следующие изменения проверялись. Старые спасения без записи
идентичности принимаются с предупреждением. Если стабильных идентификаторов нет, программа предупреждает, что
надёжно проверить источник не может.

lastread сравнивает доступные цепочки блочных устройств источника и назначения, в том числе device-mapper и RAID.
Если цепочку определить не удалось или используется многодисковая файловая система, например btrfs, программа
предупреждает: убедитесь самостоятельно, что все устройства назначения находятся на другом физическом диске.
Эти проверки помогают, но не дают полной гарантии.

## Рецепты

### Проверить диск до долгого запуска

```bash
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK --triage
```

Проверка читает девять проб по 1 МиБ (начало, семь точек между, конец) — на каждую до `--triage-timeout` секунд, —
останавливается после двух неудач подряд или после одного чтения, которое не вернулось, и больше ничего не читает.
Пробное чтение на больном диске всё же чтение, поэтому оно короткое. Вердикт — эвристика: зелёный — «в этой короткой
проверке ничего тревожного», жёлтый — «можно работать, ждите неприятностей», красный — «диск почти не отвечает» (код
выхода 4). Часть про SMART читается из `smartctl -j` (обычный вызов, затем `-d sat` для диска за USB-мостом); она написана
по описанной схеме JSON и проверена на подготовленных документах, а не на настоящих дисках.

### Следить за долгим спасением

Спасение идёт днями и порой останавливается для выключения питания. Помогают три средства:

```bash
lastread --status --dir /mnt/big/rescue --name old-disk          # без root, диск не трогает
lastread --status --json --dir /mnt/big/rescue --name old-disk   # для мониторинга (нужен jq)
sudo lastread DISK --dir /mnt/big/rescue --on-event ~/notify.sh  # на события запускается программа
```

`--status` показывает, идёт ли спасение, следующую фазу, долю спасённого, непрочитанное и нечитаемое, скорость за
последние десять минут с грубой оценкой оставшегося времени, температуру, отложенные зоны и последние строки журнала.
`--on-event ПРОГРАММА` запускает в фоне `ПРОГРАММА СОБЫТИЕ СООБЩЕНИЕ` (без оболочки; в окружении `LASTREAD_EVENT`,
`LASTREAD_MESSAGE`, `LASTREAD_NAME`, `LASTREAD_DIR`, `LASTREAD_STATUS`) при событиях: `started`, `hot`, `cooled`,
`dropped`, `recovered`, `power-cycle`, `zones-stuck`, `phase-done`, `done`, `interrupted`, `failed`. Упавшая программа
спасение не останавливает.

Чтобы спасение само продолжилось после выключения питания, отдайте его systemd:

```bash
lastread DISK --dir /mnt/big/rescue --name old-disk --print-service | sudo tee /etc/systemd/system/lastread-old-disk.service
sudo systemctl daemon-reload && sudo systemctl enable --now lastread-old-disk.service
```

Юнит перезапускает инструмент после обычной ошибки (несколько раз), но не после кода 3 (нужно выключить питание —
следующий запуск будет при очередной загрузке), 2 (застрявшие зоны — нужно решение) и не после остановки через
`systemctl`. Когда спасение закончено: `systemctl disable lastread-old-disk.service`.

### Важные файлы — первыми

```bash
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK-part1 --dir /mnt/big/rescue --first 'Documents' --first 'Photos/2019'
```

На NTFS сначала читаются структуры, нужные, чтобы знать файлы (фаза `meta`), затем данные указанных путей, затем
остальное. Без `--first` структуры всё равно читаются первыми; `--no-meta-first` отключает фазу. Отложенные зоны в
этой фазе не читаются: место, где диск зависает, откладывается как всегда. Для тома не NTFS фаза так и скажет, и
дальше идёт обычный порядок.

### Диск целиком вместо раздела

```bash
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK --dir /mnt/big/rescue --name old-disk --extract --extract-to /mnt/recovered
```

Если у образа есть таблица разделов, единственный раздел с читаемой файловой системой (NTFS, ext2/3/4, FAT, exFAT)
находится и используется (через `mmls`); если их
несколько, инструмент скажет об этом, а `--partition N` выберет (N считает разделы так же, как `/dev/sdX1`,
`/dev/sdX2` …). Другие файловые системы снимаются как обычно, а файловый уровень говорит, почему пропущен.

### Мусор, который диск отдаёт без ошибки

Раскладка уже перечисляет файлы с подозрительными данными (см. совет про тихую порчу). С `--recheck-garbage` инструмент
идёт дальше: один раз, после copy, scrape и retry, он просматривает *образ* на подозрительный шаблон (служебный сектор
`sEDU` или ваш `--suspect-pattern`; проверка серий нулей здесь не используется: нули в неиспользуемом месте обычны),
помечает эти сектора нечитаемыми, чтобы фаза retry попросила их у диска ещё раз (изношенный диск иногда со второго раза
отвечает правильно), и просматривает образ снова. То, что всё ещё похоже на мусор, записывается в
`ИМЯ.logs/garbage-ranges.txt` и считается нечитаемым: файлы, которые его задевают, повреждены и не раскладываются.
Работает для любой файловой системы; образ читается целиком один раз — столько, сколько нужно `grep` на размер диска.

### Просто снять образ

```bash
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK --dir /mnt/big/rescue --name old-disk --no-fs
```

Работает для любого устройства и любой файловой системы (в том числе диска целиком с таблицей разделов). Результат —
обычный `old-disk.img` и карта; позже образ можно смонтировать только на чтение через loop-устройство
(`losetup -r -P`).

### Ноутбучный диск, который перегревается

По умолчанию остановка при 48 °C и продолжение при 44 °C. Подстройка — `--stop`/`--resume`, частота проверки —
`--interval`. За USB-мостом обычный вызов `smartctl` часто не работает; тогда инструмент сам пробует `-d sat`,
принудительно — `--smart-type sat`. Свой датчик — `--temp-cmd ./my-sensor`. Остывание идёт заметно дольше нагрева:
готовьтесь к паузам по 15–25 минут. Держите ноутбук на питании от сети: пока инструмент работает, он не даёт машине
уснуть и не реагирует на крышку (`systemd-inhibit`), но с севшей батареей ничего поделать не может.

### Диск, который отваливается от шины

Используйте имя из `/dev/disk/by-id/...` — после возврата диска инструмент определит устройство заново. На SATA/SAS он
через `--rescan-pause` секунд пересканирует SCSI-хост (`echo "- - -" > /sys/class/scsi_host/hostN/scan`, от root), до
`--rescan-attempts` раз подряд без продвижения, затем попросит выключить питание. Хост запоминается в
`ИМЯ.logs/scsi-host`, так что следующий запуск может вернуть пропавший диск ещё до начала работы. Для ядра таймаут
команды 30 с означает сброс связи после долгого перечитывания и, после нескольких сбросов, отключение диска; пока
идёт спасение, инструмент поднимает его до `--kernel-timeout` (180 с) и при выходе возвращает прежнее значение.

На USB и NVMe нет пересканирования хоста, которое оживило бы устройство: инструмент так и скажет и попросит
выключить питание (вытащить и вставить диск или выключить и включить машину).

### Что уже спасено, без диска

```bash
sudo lastread --inventory --dir /mnt/big/rescue --name old-disk
```

Работает на любой стадии, даже посреди спасения (откажет, если образ занят другим запуском). Выдаёт целые и неполные
файлы.

### Сначала спасти конкретные файлы

```bash
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK-part1 --dir /mnt/big/rescue --file 'Семейные фото/2019'
sudo lastread /dev/disk/by-id/ata-EXAMPLE_DISK-part1 --dir /mnt/big/rescue --pick
```

ddrescue читает только данные неполных файлов, в чьём пути есть этот текст (или которые вы отметили в окне): copy,
scrape и retry — только в их пределах, затем файлы перепроверяются. С `--extract --extract-to КАТАЛОГ` ставшие целыми
сразу раскладываются. Обычное спасение продолжается той же командой без `--file`/`--pick`.

### Раскладка

```bash
sudo lastread --inventory --dir /mnt/big/rescue --name old-disk --extract --extract-to /mnt/recovered \
    --include Photos --map Documents/Work:work-docs --owner alice
```

Дерево тома сохраняется внутри `--extract-to`. `--include` оставляет только указанные пути; `--map ИСТОЧНИК:КУДА`
кладёт каталог (или один файл) в каталог `КУДА`; при любом из них раскладываются только подходящие файлы. Без них
раскладывается весь том — вместе со служебными папками вроде `System Volume Information` и файлами вроде
`pagefile.sys`, поэтому выбирайте нужное через `--include`. С `--inventory` параметры `--include`/`--map` лишь выбирают
пути, для которых печатаются счётчики (без них счётчики — по каталогам верхнего уровня). Файлы пишутся как `ИМЯ.part` и
переименовываются по завершении; время изменения берётся из тома. Файл, уже лежащий на месте с тем же размером и
временем, пропускается, поэтому раскладку можно прерывать и повторять.

По умолчанию раскладываются только **целые** файлы. В обычном запуске `--extract-damaged` раскладывает и повреждённые
файлы, нечитаемые части в них — нули; следующие запуски такой файл пропустят, потому что размер и время совпадают, —
перед повторным спасением удалите его.

### Пропустить медленные места

```bash
sudo lastread ИСТОЧНИК --dir D --min-rate 20M --skip-size 1Mi,1Gi
sudo lastread ИСТОЧНИК --dir D --reverse            # фаза copy от конца к началу
sudo lastread ИСТОЧНИК --dir D --start-at 1700G      # только первый запуск: начать отсюда
```

### Бросить зону, которую диск не читает

Когда остались только застрявшие зоны, инструмент завершается с кодом 2. Чтобы перестать их пробовать и считать файлы
внутри повреждёнными, запустите ту же команду с `--give-up-zones`.

## Советы

- **Диск не держит связь:** попробуйте принудительно понизить скорость SATA параметром ядра
  `libata.force=N:1.5Gbps` (`N` — номер ATA-порта из `dmesg | grep -i 'ata[0-9]'`; синтаксис — в
  `kernel-parameters.txt` ядра). Потом уберите.
- **Холодное выключение:** если диск отвалился и пересканирование его не вернуло, выключите питание полностью (не
  перезагрузка), подождите, включите и запустите ту же команду (или поручите последний шаг `--print-service`).
- **Флаг «только чтение».** lastread пытается установить `blockdev --setro` как дополнительную защиту ядра от
  случайной записи. Если это не удалось, он предупреждает и продолжает без защиты. При штатной очистке прежнее
  значение возвращается; вернувшемуся устройству флаг устанавливается снова. `--no-readonly` отключает это.
- **Тихая порча.** Некоторые умирающие диски отдают вместо данных что-то другое и не сообщают об ошибке, так что
  ddrescue считает место прочитанным. При раскладке поток данных проверяется, подозрительные файлы попадают в
  `suspicious-files.txt` (но всё равно раскладываются): 512-байтный служебный сектор с меткой `sEDU` в начале и в
  конце (замечен на умирающем 2,5" SMR-диске) и, по умолчанию, 128 КиБ нулей подряд. Длинные серии нулей законны в
  разреженных файлах, образах дисков и некоторых базах данных: увеличьте `--suspect-zeros РАЗМЕР` или отключите
  проверку (`--suspect-zeros 0`, `--no-suspect-check`). Шаблон заменяется через `--suspect-pattern RE` (`grep -P`,
  байты).
- **Перепроверьте приёмник после внезапного отключения.** Пропуск «уже разложенных» файлов по размеру и времени не
  ловит файл, запись которого оборвалась (например, USB-мост терял данные при отключении). Используйте `--verify`:
  каждый разложенный файл синхронизируется, выбрасывается из кэша, читается обратно и сравнивается по SHA-256 с тем,
  что дал образ; хеши попадают в `ИМЯ.logs/manifest.sha256` (`cd ПРИЁМНИК && sha256sum -c МАНИФЕСТ` проверит их позже
  и где угодно); файлы, уже лежащие на месте, проверяются так же — по манифесту или, если записи нет, по образу — и
  раскладываются заново, если отличаются.
- **Запускайте в `tmux`/`screen`** и держите образ на диске со свободным местом на всё устройство.
- **Образ разреженный** и растёт по мере чтения; `truncate` задаёт ему размер устройства.

## Ограничения

- Файловый уровень поддерживает NTFS (обычные, резидентные, разреженные, сжатые и сильно раздробленные файлы), ext2/3/4
  (экстенты, дыры, данные внутри inode), FAT12/16/32 и exFAT — на образе раздела или на разделе образа диска целиком.
  Фаза «структуры первыми» и поиск записей, до которых не дошёл обход каталогов, есть только для NTFS и ext (FAT/exFAT
  перечисляются обходом). Время FAT хранится без часового пояса и принимается за UTC. Остальные файловые системы
  (btrfs, XFS, APFS …) снимаются как обычно, а файловый уровень говорит, почему пропущен. Другие файловые системы снимаются как обычно, а файловый
  уровень говорит, почему пропущен. Код устроен так, чтобы позже можно было добавить другие файловые системы, которые понимает
  The Sleuth Kit; эта версия их не обещает.
- Именованные потоки и служебные файлы (`$…`) не перечисляются; имена файлов с символом табуляции нельзя положить в
  списки, они выводятся как `?/entry N`.
- Зашифрованные (EFS) файлы копируются как лежат на диске.
- Без The Sleuth Kit `--extract`, `--inventory`, `--pick` и `--file` отказываются запускаться; обычный запуск всё равно
  снимет образ, сообщит, что файловый уровень не сделан, и не запишет отчёт как готовый — повторный запуск после
  установки `sleuthkit` его сделает.
- Нет починки, нет записи на источник, нет графического интерфейса, нет поддержки Windows и macOS.
- Сброс USB-устройства (`authorized`) не реализован.

## Разработка

```bash
tests/lint.sh                 # ShellCheck и правила оформления
tests/unit/run.sh             # модульные тесты: без root и без устройств
tests/vm.sh create            # создать ВМ Multipass с зависимостями
tests/vm.sh integration       # тесты device-mapper, scsi_debug, NTFS, ext4, FAT32 и exFAT — от root в ВМ
```

Интеграционные тесты создают и удаляют блочные устройства: запускайте их в ВМ, а не на машине, чьи диски дороги.
`docs/feature-matrix.md` связывает каждую функцию с кодом и тестом.
